# 2.1.3 Patch Release Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** PR #241의 보안·로직·공급망 개선을 프로젝트 2.x 패치 릴리스 `2.1.3`으로 문서화하고, 검증된 `main` 커밋에 태그를 생성해 GitHub Release를 발행한다.

**Architecture:** 프로젝트 버전은 `build.gradle.kts`의 Axion Release Plugin이 Git 태그에서 계산하므로 별도 버전 상수나 Gradle 프로퍼티를 수정하지 않는다. 릴리스 준비 PR에서는 영어·한국어 README의 소비자 버전만 동기화하고, 병합된 `main`에서 로컬 태그 생성과 검토를 분리한 뒤 승인된 태그만 원격에 푸시한다.

**Tech Stack:** Gradle 9.7.1, Axion Release Plugin 1.21.3, Java toolchain 17, JDK 17/21/25, GitHub Actions, JitPack.

**Spec:** `docs/superpowers/specs/2026-08-30-audit-remediation-scope.md`; release policy: `MAINTENANCE.md`

## Global Constraints

- 목표 버전은 `2.1.3`이며 2.x 활성 릴리스 브랜치는 `main`이다.
- `1.1.2`는 Spring Boot 3.5용 유지보수 버전이므로 변경하지 않는다.
- 새 의존성, 제품 코드, 공개 API/ABI, Gradle 플러그인 ID를 변경하지 않는다.
- 영어 및 한국어 README의 코드 블록과 버전 예제를 동일하게 유지한다.
- Java 17 바이트코드와 JDK 17/21/25 검증 범위를 유지한다.
- 원격 태그 푸시와 GitHub Release 생성은 외부 가시 작업이므로 승인된 실행 단계에서만 수행한다.
- 공개된 릴리스 태그는 이동하거나 재사용하지 않는다. 원격 태그 이후 결함은 `2.1.4`로 수정한다.

### Task 1: 2.1.3 릴리스 문서 준비

**Files:**
- Modify: `README.md`
- Modify: `README.ko.md`

**Interfaces:**
- Consumes: Axion이 계산한 현재 개발 버전 `2.1.3-SNAPSHOT`
- Produces: 모든 2.x 소비자 예제가 `2.1.3`을 가리키는 동기화된 영어·한국어 README

- [x] **Step 1: 깨끗한 최신 main에서 릴리스 브랜치 생성**

```bash
git switch main

git pull --ff-only origin main

```

Expected: tracked 변경이 없는 `main`이 최신화되고, 현재 계획 파일을 유지한 채 `release/2.1.3`이 생성된다.

- [x] **Step 2: 태그 기반 개발 버전과 태그 부재 확인**

```bash
./gradlew currentVersion --dependency-verification=strict --no-daemon -q
! git rev-parse --verify refs/tags/2.1.3
```

Expected: `Project version: 2.1.3-SNAPSHOT`이 출력되고 `2.1.3` 태그는 아직 없다.

- [x] **Step 3: 영어·한국어 README의 2.x 버전 12곳 갱신**

`README.md`와 `README.ko.md`에서 각각 다음 여섯 종류의 `2.1.2` 참조를 `2.1.3`으로 바꾼다.

1. 버전 지원 표의 latest release
2. JitPack 제공 버전 설명
3. Gradle 플러그인 classpath
4. `restdocs-api-spec` 테스트 의존성
5. `restdocs-api-spec-mockmvc` 테스트 의존성
6. `restdocs-api-spec-webtestclient` 테스트 의존성

`1.1.2` 및 예제 API 버전 `0.1.0`은 유지한다.

- [x] **Step 4: README 버전과 코드 블록 동기화 검증**

```bash
! rg -n '2\.1\.2' README.md README.ko.md

- [x] **Step 5: 릴리스 준비 문서 커밋**

### Task 2: 릴리스 후보 검증 및 PR

**Files:**
- Verify: all tracked files

**Interfaces:**
- Consumes: `release/2.1.3`의 README 버전 커밋
- Produces: strict dependency verification과 적용 가능한 PR 상태 확인을 마친 `main` 대상 릴리스 준비 PR

- [x] **Step 1: JDK 17에서 전체 로컬 검증**

```bash
./gradlew -Dorg.gradle.java.installations.fromEnv=JAVA_HOME_17_X64 \
  --dependency-verification=strict \
  clean check testCodeCoverageReport :restdocs-api-spec-example:openapi3 --no-daemon

javap -verbose \
  restdocs-api-spec-generator/build/classes/kotlin/main/com/keecon/restdocs/apispec/generator/OpenApi3Generator.class \
  | rg 'major version: 61'

Expected: 전체 빌드가 성공하고 클래스 major version가 61이다. OpenAPI SHA-256은 릴리스 PR에 기록한다.

- [x] **Step 2: 브랜치 푸시 및 main 대상 PR 생성**

```bash
git push -u origin release/2.1.3
gh pr create \
  --base main \
  --head release/2.1.3 \
  --title "docs: prepare 2.1.3 release" \
  --body "Update the English and Korean usage documentation to 2.1.3 after the audited patch changes."
```

- [x] **Step 3: PR 필수 상태 확인**

```bash
pr_number=$(gh pr list --state open --head release/2.1.3 \
  --json number --jq '.[0].number')
test -n "$pr_number"
gh pr checks "$pr_number" --watch --interval 10
gh pr view "$pr_number" \
  --json state,isDraft,mergeable,mergeStateStatus,reviewDecision,statusCheckRollup
```

Expected: CI가 실행되면 JDK 17/21/25와 Codecov project/patch가 모두 성공한다. 모든 변경이
`paths-ignore` 대상이면 체크가 생성되지 않은 이유를 기록한다. 어느 경우든 PR은 `MERGEABLE/CLEAN`이어야 하며,
태그의 JDK 17/21/25 검증은 Task 4의 release workflow가 보장한다.

- [x] **Step 4: 승인된 방식으로 PR 병합 후 main 최신화**

```bash
pr_number=$(gh pr list --state open --head release/2.1.3 \
  --json number --jq '.[0].number')
test -n "$pr_number"
gh pr merge "$pr_number" --squash
git switch main
git pull --ff-only origin main
test -z "$(git status --porcelain)"
```

Expected: 릴리스 준비 커밋이 `origin/main`에 포함되고 로컬 `main`이 깨끗하다.

### Task 3: 2.1.3 태그 생성 및 사전 검토

**Files:**
- Verify: Git repository state and Axion-computed version

**Interfaces:**
- Consumes: 검증된 릴리스 준비 squash 커밋
- Produces: 아직 원격에 푸시하지 않은 로컬 `2.1.3` 태그

- [x] **Step 1: 태그 생성 전 main과 버전 상태 재검증**

```bash

git fetch origin main --tags

! git rev-parse --verify refs/tags/2.1.3
./gradlew currentVersion --dependency-verification=strict --no-daemon -q
./gradlew verifyRelease -Prelease.version=2.1.3 \
  --dependency-verification=strict --no-daemon
```

Expected: 태그가 없고 현재 개발 버전은 `2.1.3-SNAPSHOT`이며 `verifyRelease`가 성공한다.

- [x] **Step 2: 로컬 태그만 생성**

```bash
./gradlew createRelease -Prelease.version=2.1.3 \
  --dependency-verification=strict --no-daemon
```

Expected: 로컬 `2.1.3` 태그가 생성되지만 `refs/tags/2.1.3`은 아직 원격에 없다.

- [x] **Step 3: 태그 대상과 버전 검토**

```bash

git merge-base --is-ancestor 2.1.3 origin/main

./gradlew currentVersion --dependency-verification=strict --no-daemon -q
! git ls-remote --exit-code --tags origin refs/tags/2.1.3
```

Expected: 태그는 현재 `main` HEAD를 가리키며 계산 버전이 `2.1.3`이고 원격에는 아직 없다.

## Failure and Recovery Rules

- 원격 푸시 전 로컬 태그 검증이 실패하면 `git tag -d 2.1.3`으로 로컬 태그만 제거하고 원인을 수정한다.
- 원격 태그 푸시 후 workflow가 일시적으로 실패하면 로그를 조사해 동일 커밋에서 안전한 재실행 가능 여부를 판단한다.
- 원격 태그가 공개된 뒤 코드나 릴리스 내용의 수정이 필요하면 `2.1.3` 태그를 이동·삭제하지 않고 `2.1.4` 패치 릴리스를 준비한다.
- JitPack 확인은 공개된 `2.1.3` 좌표의 기존 빌드를 읽기 전용으로 조회하며, 별도 빌드 트리거가 필요하면 사용자 승인을 받는다.
